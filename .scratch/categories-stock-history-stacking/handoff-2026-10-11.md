### Migration 006: written and DB-tested
`backend/src/db/migrations/006_categories_stock_history_stacking.sql` covers:
- `stock_changes` table plus trigger `log_stock_change` on products. `stock_context(kind, order, actor, note)` tags changes through transaction-local `set_config`. One `opening` row per existing product.
- `set_product_on_hand(product, on_hand, actor, note)`: refuses `BELOW_RESERVED` with DETAIL = the minimum. `adjust_product_stock` is **dropped**.
- `categories` table (slug PK, `is_system`, delete trigger), seeded with the 4 existing Categories. `products.category` now has an FK to it (the CHECK was dropped).
- `beetle_families` table seeded from products, plus `rename_beetle_family()`.
- `promotions.stacking` (default `exclusive`) and `previewed_at`. `order_items.promotion_ids UUID[]`. `line_promotion_ids()` helper.
- `notifications.promotion_id` FK with ON DELETE CASCADE, back-filled from the JSON. Unique indexes are now per recipient. New types: `confirmed_by_admin`, `confirmed_auto`, `admin_confirmed_by_customer`, `admin_confirmed_auto`, `promotion_new`.
- `notify_order_event` handles Confirmed. `send_confirm_requests` uses the new ON CONFLICT target. `announce_promotions()` replaces `announce_started_promotions()` (dropped): it sends "coming" with dates, then "started", and only "started" when the Promotion is first seen on or after its start.
- `create_order`, `cancel_order` and `confirm_order` are re-created from 005 with `PERFORM stock_context(...)`. `create_order` also accepts `promotion_ids` per line and checks they are ⊆ `p_redeem`.
- **Edit 006 directly from now on.** It was produced once by a throwaway generator; that generator is gone. All UPDATE/DELETE statements need a WHERE (the test checks this, because Supabase runs pg-safeupdate).

## Notes and gotchas
- Files use CRLF. The Bash tool here mangles big heredocs containing quotes, so write a Python script with the Write tool and run it. In Python, open files in text mode; it keeps CRLF.
- Locale edits: load and dump the JSON with `ensure_ascii=False, indent=2` plus a trailing newline. The files round-trip identically. `locales.test.ts` checks that TH and EN have the same keys.
- Spec decision: the product-created Stock Change has no actor, because products are inserted directly via supabase-js. Accepted.
- Decisions the user approved: Stackable percentages compound, then baht come off, never below 0; one Redemption per Promotion per order; existing Promotions are Exclusive; the beetle Category is locked; slugs never change; a Family rename cascades to products; LINE goes only to the Owner and only on customer confirm, and a LINE failure is only logged.
